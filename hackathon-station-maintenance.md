# Hackathon Station maintenance

Use this Skill when maintaining the local **Hackathon Station** mini-app (numeric app 12, slug `hackathon-gallery`), including its intro, 3D journey, curation, public submissions, leaderboards, or bundled assets. Read the app's `README.md` and `INTEGRATION.md` for its present contract, and inspect current source/data before acting. This Skill is a maintenance map, not a claim that a past test still passes.

## Ownership boundaries

- The owner chose to keep all archive-supplied `src/*.js`, `src/station.css`, and `assets/*` byte-identical to `hackathon-station.zip`. Put new intro presentation and compatibility fixes in app-owned wrapper files, unless the owner explicitly changes that direction.
- The original module entry is `src/main.js:mountStation`. `index.jsx` is the Möbius wrapper; `station-css.js` is an exact JS-string copy of the supplied CSS. The app-owned presentation file is `station-cinematic-style.js`; `station-tools-style.js` positions the retained Admin, leaderboard, and About controls. Do not introduce a second intro or make START/SKIP wait.
- `station-world-details.js` decorates the existing `STATION_MOUTH` in the active flight scene and shows nearby-art/bridge-trophy information without editing supplied meshes or room modules. It hooks the returned engine's scene setter and restores it on dispose; keep the card non-interactive and sourced from approved art/winners. Package credits establish station concept/art direction, not a separate named designer for each procedural trophy.
- `station-service.js` is the only transport module: `requestGallery` (authenticated curator lane), `publicRequest` (visitor lane) and `createVisitorApi`, which reads through the curator lane once and falls back to the public lane for a published visitor. `station-participant.js`/`.jsx` hold sign-in and work submission; `station-score.js` synthesises the soundtrack. Keep all four app-owned: the supplied package has no loader, identity or music seam.
- `station-presence.js` decorates the existing walkable scenes with opt-in peer pilot models. Its public `presence` call in `service.py` uses short-lived positions in `gallery.sqlite3`, eight-second client updates, a 30-second expiry and bounded room roster. Callsigns are self-declared and never authorize official scores. Keep this off by default and do not promise frame-accurate multiplayer or weaken the platform's public-service rate limit.
- `station-score.js` never edits supplied scenes. It classifies the active scene wrapper (the flight wrapper's own `mode`, or a room's GLB empties such as `PLACE_1`, `WINNER_SLOT_1`, `DOOR_BRIDGE_LIFT`, `DOOR_TO_CORRIDOR`) and crossfades persistent voices. Build the AudioContext on a visitor gesture, not at mount: building it early only produces a suspended context and a console warning.
- `station-image-loader.js` configures GLTFLoader's embedded image decoding through Three's image-element loader, because the opaque app frame's policy allows image object URLs but not fetches of object URLs. Do not weaken platform CSP to make a model load. Keep this configuration app-local, and remove it only if the supplied mount API gains a loader seam.
- `mobius.json` lists every supplied asset under `static_assets`; URL mapping is `/app-assets/by-id/${appId}/${name}`. Preserve the original files and credits.
- App 8 is a separate hackathon programme app. Do not edit it as part of Station work.

## Live data paths

- `station-integration.js` maps approved curated service art to `{id,title,author,caption,url}` and preserves winner-place holes. Pending submissions are not public art; sample records must not be represented as real winners. `Admin.jsx` and `service.py` own curation, moderation, and Top Pilots. App data lives separately under `/data/apps/12` and must not be reset during QA.
- Preload `hs.pilot`, `hs.xp`, and `hs.best` through `device.storage` before mounting; the supplied station expects synchronous `getItem`/`setItem`, so the adapter caches reads and writes through in order. Do not replace it with opaque-frame localStorage.
- `onEvent('flight', {score,pilot})` goes through the existing Top Pilots service. The service board limits display names to 12 characters, while the saved pilot can have 14. Test scores are real writes: inspect first and delete only exact rows created for testing, never mass-clear or remove other pilots.
- Preserve public moderated submissions and owner-only approval; do not bypass either side to make demo art appear.
- Access model (owner decision, 8 October 2026): guests explore and play freely, but artwork submission and official leaderboard entries require a participant code issued in Admin → PARTICIPANTS. `signin` exchanges a code for an HMAC token (30 days, key at `APP_STORAGE_DIR/participant.key`, re-verified on every write and on load); the device keeps it as `hs.verified` and music preferences as `hs.audio`. A flight run carries no self-declared name: the board name is the verified participant, truncated to the service's 12 characters. Do not add a way to post an official score without a token, and do not treat a callsign as an identity.
- The public lane may read `gallery`, `media/<id>` and `scores`; it must never reach curation, the queue, or `codes`.

## Verification sequence

1. Compare archive `src/*` and `assets/*` bytes with the installed files; check the exact app numeric ID and source status. Keep test data separate from live SQLite.
2. Run `node --test test_station_integration.mjs` and `python3 test_service.py -q`; run the app validator and apply with the official app scripts. Inspect the apply result, not just shell exit status.
3. In the app frame, CDP `Input.dispatchKeyEvent` does not reach the opaque child frame: hold keys by dispatching synthetic `KeyboardEvent`s on the frame's `window` through `Runtime.evaluate` (`player.js` reads `e.key`). Software rendering runs at roughly 3 fps and the engine clamps `dt`, so real-time walking covers about half a metre per wall-clock second; the Grand Gallery's 90 m needs several minutes. The spawn lane is blocked by `st_plinth_cap_1` near z≈36, so walk a clear lane at x≈2.2. Position is readable without new code by walking the React fiber from `#station-root` to the hook whose `current` holds `{engine, player}`.
4. Use the authenticated Möbius shell route and app frame for rendered checks, not a standalone demo or `?jump=` shortcut. Follow `visual-testing.md` before taking/describing screenshots. Exercise intro → pilot → hangar → flight → dock → gallery → bridge → ceremony; check the child frame console. Include a 390×844 phone check for touch layout and flight controls. A headless check cannot certify device GPU performance, audio, or physical touch feel.
5. Inspect Admin, approved collection/winner placement, public submission path, and Top Pilots as needed for the changed seam. Preserve real collection and leaderboard rows; clean only fixtures created by this run.
6. Keep all work local unless the owner specifically authorizes an upstream/public action. Station is already a mini-app in Apps, not a remote MCP server for the Integrations registry.

See app Git history and the owning chat note for dated implementation/verification history; current code and current records remain authoritative.
